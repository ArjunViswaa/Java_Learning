Section 01

OOP — Everything is an Object 🌍

In the real world, everything around you is an object — a pen, a phone, a mouse, a table, even you. Every object has two things:

📋 Properties (what it knows)

  • Pen: color, brand, height
  • Human: name, age, favourite actor
  • Phone: model, storage, battery

⚡ Behavior (what it does)

  • Pen: writes
  • Human: talks, walks, codes
  • Phone: calls, takes photos

Java is Object-Oriented Programming (OOP) — everything you build is modelled as objects with properties (variables) and behaviors (methods). From now on, think in objects: "I need an object that can add two numbers," not just "I need to add two numbers."

Section 02

Class = Blueprint, Object = Instance 🏗️

A class is a design/blueprint. An object is the actual thing built from that blueprint.

▸ Class → Object Analogy
Apple's Lesson
Apple says "Designed in California, Assembled in China." Your job is designing (writing the class). JVM does the assembling (creating the object in memory).
Section 03

Creating Your First Class & Object 🚀

javaCalculator class + Demo using it
// Class = Blueprint
class Calculator {
    int num;                          // instance variable

    public int add(int n1, int n2) {  // method
        return n1 + n2;
    }
}

class Demo {
    public static void main(String[] args) {
        // Object = Instance built from blueprint
        Calculator calc = new Calculator();

        int r1 = calc.add(3, 4);  // calling the method
        System.out.println(r1);      // Output: 7
    }
}
  1. Calculator is the class (blueprint) — has variable num and method add.
  2. new Calculator() tells JVM to create an object in heap memory.
  3. calc is the reference variable — it holds the object's address, not the object itself.
  4. calc.add(3, 4) uses the reference to call the method on the object.
You Can't Call Methods Without an Object!
Just writing add(3, 4) in Demo won't work — Java says "cannot find symbol." The method add belongs to Calculator, not Demo. You need an object of Calculator to call it.
Section 04–06

Methods — Behavior, Returns & Parameters 🔧

A method defines what an object does. Every method has: access modifier, return type, name, parameters, and body.

▸ Anatomy of a Method

void vs returning a value

void method

Does something but returns nothing.
public void playMusic()

vs

Returning method

Performs something and gives back a value.
public String getPen(int cost)

The return Keyword
return does two things: (1) sends a value back to the caller, and (2) immediately exits the method. No code after return in the same block will execute. The return type in the method signature must match what you actually return.
Section 07

Method Overloading 🔄

Same method name, different parameters. Java tells them apart by the parameter list, not the return type.

javathree overloaded add methods
class Calculator {
    public int add(int a, int b)                 { return a+b; }         // 2 ints
    public int add(int a, int b, int c)         { return a+b+c; }       // 3 ints
    public double add(double a, double b)      { return a+b; }         // 2 doubles
}
Overloading Rules
Methods must differ in number or type of parameters. Return type alone is NOT enough to distinguish them. Same name + same parameters = "duplicate method" error. This is method overloading — a form of compile-time polymorphism.
Section 08–10

JVM Memory: Stack vs Heap 🧠

▸ Stack & Heap Memory Layout
StackHeap
Local variables & method framesObjects & instance variables
LIFO (Last In, First Out)No fixed ordering
Each method gets its own frameShared across all methods
Frame destroyed when method returnsObject removed by Garbage Collector
Holds primitive values & reference addressesHolds actual object data
Instance vs Local Variables
Local variables (declared inside a method) → stored in Stack. Destroyed when method ends.
Instance variables (declared inside a class, outside methods) → stored in Heap (inside the object). Live as long as the object lives.
Section 12–15

Arrays — Multiple Values, One Variable 📦

Instead of creating 100 variables, create one array that holds 100 values.

javacreating arrays — two syntaxes
// Syntax 1: values known upfront
int[] nums = {3, 7, 2, 4};

// Syntax 2: size known, values set later (all default to 0)
int[] nums = new int[4];
nums[0] = 4;  nums[1] = 8;  nums[2] = 3;  nums[3] = 9;
Index Starts at 0!
Array of size 4 has indices 0, 1, 2, 3 — NOT 1 to 4. Accessing nums[4] throws ArrayIndexOutOfBoundsException.

Looping Through an Array

javafor loop + .length
for (int i = 0; i < nums.length; i++) {
    System.out.print(nums[i] + " ");
}
.length — Your Safety Net
Always use nums.length instead of hard-coding the size. It prevents ArrayIndexOutOfBoundsException if the array size changes later.
Section 16–17

Multi-Dimensional & Jagged Arrays 🧊

2D Array = Array of Arrays

java2D array — 3 rows × 4 columns
int[][] nums = new int[3][4];  // 3 rows, 4 cols

// Print all values with nested loop
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 4; j++) {
        System.out.print(nums[i][j] + " ");
    }
    System.out.println();
}

Jagged Array — Uneven Rows

javarows of different sizes
int[][] nums = new int[3][];    // 3 rows, columns TBD
nums[0] = new int[3];             // row 0 has 3 cols
nums[1] = new int[4];             // row 1 has 4 cols
nums[2] = new int[2];             // row 2 has 2 cols

3D arrays: add one more [] and one more nested loop. Each extra dimension = one more loop.

Math.random() returns a double between 0.0 and 1.0. Multiply by 10 (or 100) and cast to int for random integers: (int)(Math.random() * 10).

Section 18–19

Array of Objects & Enhanced For Loop 🔁

javaarray of Student objects
Student[] students = new Student[3];  // creates array, NOT 3 objects!
students[0] = s1;  students[1] = s2;  students[2] = s3;
new Student[3] ≠ 3 Objects!
This creates an array that can hold 3 Student references. It does NOT create the Student objects themselves. You must create them separately with new Student() and assign.

Enhanced For Loop (for-each)

javano counter, no index, no exception
// Simple array
for (int n : nums) {
    System.out.print(n + " ");
}

// 2D array: outer gives rows, inner gives elements
for (int[] row : nums) {
    for (int m : row) {
        System.out.print(m + " ");
    }
}

// Array of objects
for (Student st : students) {
    System.out.println(st.name + " : " + st.marks);
}
Why "Enhanced" For Loop?
No counter, no .length, no index — just "give me each element one by one." Eliminates ArrayIndexOutOfBoundsException. Use it whenever you don't need the index number. Officially called "enhanced for loop" (not for-each — Java 8 introduced a separate .forEach() method).
Section 20

Array Drawbacks ⚠️

📏
Fixed Size
Once created, you can't grow or shrink it.
🐌
Slow Insert/Search
Inserting mid-array or searching requires traversal.
🔒
Single Type Only
Can't mix int and String in one array.
📦
Contiguous Memory
Must occupy consecutive memory slots.

These drawbacks are why Java has Collections (ArrayList, HashMap, etc.) — covered later in the course.

Section 21–22

Strings — Not a Primitive! 🔤

String starts with a capital S — it's a class, not a primitive type. But Java gives it special treatment so you can use it like a primitive:

javatwo ways to create a string
// Way 1: String literal (most common, uses String Constant Pool)
String name = "Naveen";

// Way 2: new keyword (creates object in regular heap)
String name = new String("Naveen");

Useful String Methods

MethodWhat It DoesExample
charAt(i)Character at index i"Naveen".charAt(1) → 'a'
concat(s)Joins two strings"Nav".concat(" Reddy")
+ operatorConcatenation shortcut"Hello " + name
length()Number of characters"Naveen".length() → 6
hashCode()Hash value of stringUsed internally for comparisons
+ is the Only Operator That Works with Strings
No -, no *, no /. Only + — and it concatenates (joins), not adds.
Section 23

String Immutability & String Constant Pool 🔒

This is one of the most important concepts in Java. Strings are immutable — once created, their data cannot be changed.

▸ String Constant Pool in Heap
Key Takeaway
When you write name = name + " Reddy", you're NOT modifying the original "naveen" object. You're creating a brand new "naveen Reddy" object and changing the reference. The old "naveen" object still exists (unchanged) until garbage collected. That's immutability.
Section 24

Mutable Strings: StringBuffer & StringBuilder 🔓

If you need to change string data frequently (appending, inserting, deleting), use StringBuffer or StringBuilder — they're mutable.

javaStringBuffer in action
StringBuffer sb = new StringBuffer("Naveen");

sb.append(" Reddy");              // "Naveen Reddy"
sb.insert(0, "Java ");             // "Java Naveen Reddy"
sb.deleteCharAt(2);                // removes char at index 2
String str = sb.toString();       // convert back to String

System.out.println(sb.capacity()); // 16 + initial string length
System.out.println(sb.length());   // actual character count

StringBuffer

Thread-safe (synchronized). Slightly slower. Use in multi-threaded code.

vs

StringBuilder

NOT thread-safe. Faster. Use in single-threaded code (most cases).

Capacity vs Length
Length = actual number of characters stored. Capacity = total buffer space (length + 16 extra by default). The extra 16 is a buffer to avoid expensive memory relocation when you append data.
Section 25–26

Encapsulation — Protecting Your Data 🔒

Encapsulation = making variables private + providing public methods to access them. Like your brain: nobody can read your thoughts directly — they have to ask you.

javaencapsulation in action
class Human {
    private int age = 25;       // ❌ not accessible from outside
    private String name = "Naveen";

    public int getAge()        { return age; }     // ✅ controlled access
    public String getName()    { return name; }    // ✅ getter method
}

class Demo {
    public static void main(String[] args) {
        Human obj = new Human();
        // obj.name;          ❌ ERROR — private!
        System.out.println(obj.getName());  // ✅ "Naveen"
    }
}
The Encapsulation Rule
Every instance variable should be private. Access is provided through public getter/setter methods. This way, you control who can read/write the data, and you can add validation logic (e.g., age can't be negative).

A private variable is accessible only within the same class. Methods of that class can read/write it, but nothing outside can touch it directly.
Session Recap

🎯 Grand Recap — Everything at a Glance

✅ Session 3 Complete Checklist

  • Every object has properties (variables) and behaviors (methods). Java is OOP — think in objects.
  • Class = blueprint/design. Object = actual instance built from it. JVM creates objects.
  • new ClassName() creates an object in heap memory. Returns a reference (address).
  • A reference variable (like calc) holds the address, not the object itself.
  • You must have an object to call methods of another class. add() alone won't work — need calc.add().
  • Methods have: access modifier, return type, name, parameters, and body.
  • void = returns nothing. Any other type = must have a return statement.
  • return sends back a value AND immediately exits the method.
  • Method overloading: same name, different parameters (number or type). Return type alone doesn't count.
  • Stack: local variables, method frames, LIFO, destroyed when method returns.
  • Heap: objects, instance variables, expandable, cleaned by Garbage Collector.
  • Local variables = inside method → stack. Instance variables = inside class → heap (in the object).
  • Each method gets its own stack frame. Objects in heap are shared via references.
  • Multiple objects from same class = independent state. Changing one doesn't affect another.
  • Array = one variable holding multiple values of the same type. int[] nums = {3,7,2,4};
  • Array index starts at 0. Size 4 → indices 0,1,2,3. Going beyond = ArrayIndexOutOfBoundsException.
  • nums.length gives array size — use it instead of hardcoding numbers.
  • Default int array values = 0. new int[4] creates {0,0,0,0}.
  • 2D array: int[][] nums = new int[3][4]; — 3 rows, 4 cols. Access: nums[row][col].
  • Jagged array: rows have different column sizes. Specify rows first, columns individually.
  • 3D array: one more [], one more nested loop. Each dimension = one loop.
  • Math.random() → 0.0 to 1.0. Multiply + cast for integers: (int)(Math.random()*10).
  • new Student[3] creates an array for 3 references — NOT 3 objects. Create objects separately.
  • Printing an object directly gives its address. Print obj.name etc. for actual data.
  • Enhanced for loop: for (int n : nums) — no counter, no index, auto-iterates. Best for reading.
  • For 2D enhanced loop: outer gives int[] rows, inner gives individual elements.
  • Array drawbacks: fixed size, slow insert/search, single type only, contiguous memory. Collections solve these.
  • String is a class (capital S), not a primitive. Can create with literal or new.
  • charAt(i), concat(), + (concatenation), length() — key String methods.
  • + is the ONLY operator that works with Strings.
  • Strings are IMMUTABLE. "Changing" a string creates a new object; the old one stays unchanged.
  • String Constant Pool: reuses identical string literals. s1 == s2 if both point to same pool entry.
  • name = name + " Reddy" → creates new "naveen Reddy" object, changes reference, old object GC'd.
  • StringBuffer (thread-safe) and StringBuilder (faster, not thread-safe) = mutable strings.
  • StringBuffer default capacity = string length + 16. capacity() ≠ length().
  • StringBuffer methods: append(), insert(), deleteCharAt(), toString(), setLength(), ensureCapacity().
  • Encapsulation: make instance variables private, provide public getter/setter methods.
  • private = accessible only within the same class. Outside classes must use getters.
  • Rule: every instance variable should be private. Always. No exceptions.
