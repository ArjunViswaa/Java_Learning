Section 01–02

Encapsulation — Protecting Your Data 🔒

Your brain stores data (name, age, passwords). Nobody can crack open your head to read it — they have to ask you, and you decide what to share. That's encapsulation: binding data with the methods that control access to it.

▸ Encapsulation = Private Data + Public Methods
The Rule of Encapsulation
Every instance variable → private. Access only through public getter/setter methods. This lets you add validation (e.g., age can't be negative), logging, or any logic inside the methods — impossible with direct field access.
Section 03

Getters & Setters 🎛️

javacomplete encapsulated class
class Human {
    private int age;
    private String name;

    // GETTER — reads data
    public int getAge()       { return age; }
    public String getName()  { return name; }

    // SETTER — writes data
    public void setAge(int age)      { this.age = age; }
    public void setName(String name) { this.name = name; }
}
Naming Convention for Getters/Setters
Getter: get + variable name (capitalized) → getAge(). Setter: set + variable name → setAge(int). Not compulsory, but every Java developer follows it. Most IDEs auto-generate them: Right-click → Source Action → Generate Getters and Setters.
You Don't Need Both
Having only a getter (no setter) makes a variable read-only from outside. Having only a setter (no getter) makes it write-only. Choose based on your design needs.
Section 04–05

The this Keyword — Solving the Name Clash 🎯

When your method parameter has the same name as an instance variable, Java defaults to the local variable. Use this to say "I mean the instance variable, not the local one."

javathe problem and the fix
public void setAge(int age) {
    age = age;        // ❌ local = local. Instance variable stays 0!
    this.age = age;  // ✅ instance = local. Correct assignment!
}
▸ this in Stack & Heap Memory
this = the current object that called the method
When obj.setAge(30) is called, inside setAge, this refers to obj — the exact same address (101). Java provides this automatically; you never need to pass the object to its own methods.
Section 06–08

Constructors — Initializing Objects at Birth 🏗️

A constructor is a special method that runs automatically when you create an object. It initializes the object's state.

RuleDetail
NameMust be same as class name
Return typeNone — not even void
CalledAutomatically on new ClassName()
DefaultIf you write none, Java provides a blank one
OverloadingMultiple constructors with different params ✅
javadefault + parameterized constructors
class Human {
    private int age;  private String name;

    // Default constructor — no params, default values
    public Human() {
        this.age = 12;
        this.name = "John";
    }

    // Parameterized constructor — custom values
    public Human(int age, String name) {
        this.age = age;
        this.name = name;
    }
}

// Usage:
Human obj  = new Human();            // John, 12
Human obj1 = new Human(18, "Naveen"); // Naveen, 18
The Hidden Default Constructor
If you write zero constructors, Java creates a blank default one behind the scenes: public Human() { }. But the moment you write any constructor (even parameterized), the auto-generated default disappears. If you still need the no-arg version, you must write it explicitly.
Section 10–12

Static — Shared Across All Objects ⚡

Static Variables

A static variable belongs to the class, not to any individual object. All objects share the same copy.

▸ Instance vs Static Variables in Memory

Static Methods

javastatic method rules
class Mobile {
    String brand;               // instance
    static String name;        // static (shared)

    public static void show() {
        System.out.println(name);   // ✅ static → static OK
        // System.out.println(brand); ❌ instance in static → ERROR!
    }
}
// Call: Mobile.show(); — no object needed!
Why main is Static
main is the entry point — JVM calls it before any object exists. If main weren't static, you'd need an object to call it. But you can't create an object before execution starts. Deadlock! Making main static breaks the chicken-and-egg problem.
Section 13–14

Static Blocks & Class Loading 🔄

javastatic block runs once, before constructor
class Mobile {
    static String name;

    static {
        name = "phone";
        System.out.println("static block");  // runs ONCE
    }

    public Mobile() {
        System.out.println("constructor");    // runs per object
    }
}
// new Mobile(); new Mobile();
// Output: static block → constructor → constructor
▸ Class Loading → Static Block → Constructor Flow

Class.forName("Mobile") manually loads a class without creating an object — triggers the static block only.

Section 16

Anonymous Objects — No Name, No Reuse 👻

javaanonymous object — used once
// Normal: referenced, reusable
A obj = new A();
obj.show();
obj.show();  // same object, reused

// Anonymous: no reference, one-time use
new A().show();  // object created, show called, then lost
new A().show();  // creates a DIFFERENT object!

Anonymous objects live only in the heap — no reference variable in the stack. Useful when you need an object for exactly one operation.

Section 17–19

Inheritance — IS-A Relationship 🧬

A child class inherits all features (variables + methods) of its parent class, and can add its own.

▸ Single-Level & Multi-Level Inheritance
javaextends keyword
class AdvCalc extends Calc {
    // inherits add(), sub() from Calc
    // adds its own: multi(), div()
}
For Inheritance You Need .class, Not .java
Even if you delete Calc.java, as long as Calc.class exists, AdvCalc extends Calc still works. Inheritance uses compiled bytecode, not source code.
Section 20

Why No Multiple Inheritance? — The Ambiguity Problem 💥

▸ The Diamond / Ambiguity Problem
C++ allows it, Java doesn't
class C extends A, B → ❌ Compile error. If both A and B have show(), which one does C inherit? That's the ambiguity problem. Java's solution: no multiple class inheritance. (Interfaces provide a workaround — covered later.)
Section 21–23

super() and this() — Constructor Chaining 🔗

▸ Constructor Call Chain with super() and this()
KeywordWhat It CallsWhere
super()Constructor of parent classFirst line, auto-inserted if missing
super(args)Parameterized parent constructorMust write explicitly
this()Another constructor of same classMust write explicitly
Every Class Extends Object
Even if you don't write it, every Java class implicitly extends java.lang.Object. When A calls super(), it calls Object's constructor. This is multi-level: Object → A → B. The Object class provides methods like toString(), equals(), hashCode().
Section 24

Method Overriding — Same Signature, Different Behavior 🔀

Overloading

Same name, different params.
Same class. Compile-time.

vs

Overriding

Same name, same params.
Parent-child. Runtime.

javaoverriding add in AdvCalc
class Calc {
    public int add(int a, int b) { return a + b; }
}

class AdvCalc extends Calc {
    public int add(int a, int b) { return a + b + 1; }  // overridden!
}
// AdvCalc obj = new AdvCalc();
// obj.add(3,4) → 8 (uses AdvCalc's version, not Calc's)
The Phone Analogy
In 10th grade, if someone asks "which phone?" you say your dad's Nokia 3310 (inherited). By 12th grade, you got your own Motorola C168. Now you say C168 — your own overrides the inherited one. But dad still has his 3310.
Section 25–26

Packages — Organizing Your Code 📦

Packages = folders for classes. They prevent name clashes and create logical grouping.

javadeclaring and importing packages
// In Calc.java:
package tools;      // this class lives in the "tools" folder

// In Demo.java:
import tools.Calc;            // import one class
import tools.*;               // import ALL classes in tools
import java.util.ArrayList;   // Java's built-in
java.lang.* is Auto-Imported
String, System, Math, Object — all live in java.lang. Java imports this package automatically. That's why you never write import java.lang.String;.
* Imports Files, Not Sub-Folders
import other.* imports all classes directly in the other folder. It does NOT import classes inside other/tools/. For those, you need import other.tools.* separately.

For unique global packages, reverse your domain: com.google.calculator.

Section 27

Access Modifiers — The Full Picture 🛡️

▸ Access Modifier Visibility Chart
One Public Class Per File
A .java file can have only one public class, and its name must match the file name. Other classes in the same file must be non-public (default access). In practice, put one class per file.
Session Recap

🎯 Grand Recap — Everything at a Glance

✅ Session 4 Complete Checklist

  • Encapsulation = private variables + public getter/setter methods. Bind data with methods.
  • Every instance variable should be private. Access only through methods.
  • Getter reads (getAge()), setter writes (setAge(int)). Naming = get/set + variable name.
  • IDE can auto-generate getters/setters: Right-click → Source Action → Generate.
  • this = reference to the current object calling the method. Resolves local vs instance name clashes.
  • When local and instance variables share a name, Java defaults to local. Use this.variable for instance.
  • Constructor: special method, same name as class, no return type, called on new.
  • Default constructor = no params, auto-provided if you write none. Disappears if you write any constructor.
  • Parameterized constructor = accepts values at object creation. Constructor overloading = multiple constructors.
  • Static variable = belongs to class, shared by all objects. Access via ClassName.var.
  • Static method = called via class name, no object needed. Can't access non-static variables directly.
  • Non-static methods can use static variables. Static methods can use non-static only via object reference.
  • main is static because JVM must call it before any object exists.
  • Static block: runs once when class loads, before any constructor. Syntax: static { ... }.
  • Class loading happens once. Static block initializes static variables. Class.forName("X") loads manually.
  • CamelCase: Class = PascalCase, method/variable = camelCase, constant = ALL_CAPS, package = lowercase.
  • Anonymous object: new A().show() — no reference, can't reuse. Each new creates a different object.
  • Inheritance: child class extends parent, gets all features. IS-A relationship.
  • Superclass/parent/base = upper class. Subclass/child/derived = lower class.
  • Single-level = one parent-child. Multi-level = chain: A → B → C.
  • Multiple inheritance NOT supported in Java (ambiguity problem). C++ supports it, Java doesn't.
  • super() = calls parent constructor. Auto-inserted as first line if not written. Can pass args: super(5).
  • this() = calls another constructor of same class. Must be first line. Can't use both this() and super().
  • Every class implicitly extends java.lang.Object. Object is the ultimate parent.
  • Method overriding: same name + same params in parent-child. Child's version takes priority.
  • Overloading = same name, different params, same class. Overriding = same name, same params, parent-child.
  • Packages = folders for classes. package tools; declares. import tools.Calc; uses.
  • import pkg.* imports all files in that folder, NOT sub-folders. Need separate import for sub-packages.
  • java.lang.* auto-imported — String, System, Math, Object live there.
  • Unique packages: reverse domain name — com.google.calculator.
  • 4 access modifiers: public (everywhere), protected (same pkg + subclasses), default (same pkg), private (same class).
  • Best practice: classes → public, variables → private, methods → public. Avoid default. Use protected sparingly.
  • One public class per .java file. Its name must match the file name.

🌟 New Facts & Additions Worth Knowing

  • @Override annotation: While not mentioned in the session, always add @Override above overridden methods. It tells the compiler to verify the override is correct — catches typos in method names at compile time instead of runtime.
  • Constructor chaining with this(): A common pattern is having the default constructor call the parameterized one with default values: public Human() { this(12, "John"); }. This avoids code duplication between constructors.
  • final keyword: Not covered yet, but closely related — final variables can't be changed (true constants), final methods can't be overridden, final classes can't be inherited. Coming in a future session.
  • Static imports: You can import static members directly: import static java.lang.Math.PI; then use PI instead of Math.PI. Useful for constants and utility methods.
  • Record classes (Java 16+): Modern Java introduced record — a compact way to create immutable data classes with auto-generated constructors, getters, equals(), hashCode(), and toString(). Essentially encapsulation in one line.
  • Sealed classes (Java 17+): You can now restrict which classes can extend yours using sealed + permits. Gives finer control over inheritance hierarchies.
  • Pattern matching for instanceof (Java 16+): Simplifies type checking and casting in one step — reduces boilerplate in overriding scenarios.
