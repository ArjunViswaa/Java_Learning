Section 01

Literals Deep Dive 🔢

We learned about literals in Notes #1 — they're the raw values you type in code. But Java supports more than just decimal numbers. You can write values in binary, hexadecimal, and even use underscores for readability.

Binary Literals (Base 2)

Prefix with 0b or 0B. Java stores it as a normal int but you write it in binary form.

javabinary literal
int num1 = 0b101;   // binary 101 = decimal 5
System.out.println(num1);  // Output: 5

Hexadecimal Literals (Base 16)

Prefix with 0x or 0X. Digits go from 0–9 and A–F.

javahex literal
int num1 = 0x7E;    // hex 7E = decimal 126
System.out.println(num1);  // Output: 126

Underscores in Numeric Literals

Ever get confused counting zeros? Java lets you put underscores between digits for readability. They're ignored by the compiler.

javaunderscore readability
int bigNum = 10_00_00_000;  // same as 100000000
System.out.println(bigNum);    // Output: 100000000

Float & Double Literals — Scientific Notation

You can assign integer values to double/float (auto-widening), and use e for scientific notation:

javascientific notation
double num1 = 56;        // int → double auto-conversion → 56.0
double num1 = 12e10;     // 12 × 10^10 = 1.2E11

Boolean Literals — No 0 and 1!

Java ≠ C/C++
In Java, boolean only accepts true or false. You cannot assign 0 or 1 to a boolean. boolean b = 1; → ❌ Error! This is different from C/C++ where 0 = false and non-zero = true.

Character as Integer

Characters are internally stored as numbers (Unicode values). You can increment them!

javachar arithmetic
char c = 'a';
c++;   // 'a' becomes 'b' (97 → 98 in Unicode)
System.out.println(c);  // Output: b
Section 02

Type Conversion (Widening) 📈

Type conversion (also called implicit conversion or widening) happens automatically when you store a smaller type into a larger type. It's safe — no data loss.

▸ Widening Direction — Small → Big (automatic)
javaimplicit widening
byte b = 127;
int  a = b;   // byte → int automatically. No casting needed.
System.out.println(a);  // Output: 127
Analogy: Small Box → Big Box
You can always put a small item in a bigger box — nothing is lost. That's widening. byte → int, int → double — always safe, always automatic.
Section 03

Type Casting (Narrowing) 📉

Type casting (also called explicit conversion or narrowing) is when you force a bigger type into a smaller type. Java won't do this automatically because you might lose data — so you must explicitly say "I know what I'm doing."

javaexplicit narrowing — casting
int a = 12;
byte b = a;          // ❌ ERROR! int → byte not allowed automatically
byte b = (byte) a;  // ✅ Explicit cast. Works! 12 fits in byte range.
▸ Casting Syntax
Not Everything Can Be Cast!
You cannot cast between unrelated types. For example, char → boolean is impossible because they represent completely different things. Casting only works within the numeric family (byte, short, int, long, float, double) and with char (since char is internally a number).
Section 04

Float → Int Casting & Modulus Overflow 🔥

Float/Double → Int: Loses Decimal Part

javadecimal truncation
float f = 5.6f;
int x = (int) f;    // x = 5 (0.6 is lost!)

When you cast a decimal to an integer, the decimal part is simply chopped off (truncated, not rounded). 5.6 becomes 5, not 6.

Overflow Casting: The Modulus Rule

What happens when you cast a value that's out of range of the target type?

javaoverflow casting
int a = 257;
byte b = (byte) a;  // byte range: -128 to 127 (256 values total)
System.out.println(b);  // Output: 1
The Modulus Formula
When a value overflows during casting, Java uses modulus:

result = value % range
257 % 256 = 1

The range of byte is 256 (-128 to +127). 257 divided by 256 gives remainder 1. So b = 1.

Section 05

Type Promotion ⬆️

When you perform an operation on two smaller types, Java automatically promotes the result to a larger type to avoid overflow.

javatype promotion
byte a = 10;
byte b = 30;
int result = a * b;  // 10 × 30 = 300 → exceeds byte range!
// Java promotes byte × byte → int automatically
System.out.println(result);  // Output: 300
Why This Matters
byte × byte could overflow (max byte is 127, but 10 × 30 = 300). So Java promotes the result to int. You must store the result in an int (or larger), not a byte.
Section 06

Java Shortcut: Single-Step Run ⚡

Normally you do two steps: javac File.java then java File. But from Java 11+, you can do it in one step for single-file programs:

terminalshortcut — compile + run in one command
# Instead of two steps:
javac Hello.java
java Hello

# Do it in one:
java Hello.java   ← single step! (Java 11+)
Learning Shortcut Only!
This is only for single-file programs during learning. In real projects, you always compile separately. Also, this only works in Java 11 or newer. If it doesn't work on your machine, upgrade your JDK.

Integer Division Trap
7 / 5 = 1, not 1.4! When both operands are integers, Java performs integer division — it gives the quotient and drops the remainder. Use % to get the remainder separately. If you want 1.4, make one operand a double: 7.0 / 5.
Section 08

Compound Assignment Operators 📝

Shortcuts for "do something and assign back to the same variable":

javacompound operators
int num = 7;

num = num + 2;   // long way
num += 2;        // shortcut! same result → 9

num -= 2;        // subtract 2 → 7
num *= 8;        // multiply by 8 → 56
num /= 2;        // divide by 2 → 28
num %= 5;        // remainder of num/5 → 3
Section 09

Increment & Decrement (++/--) 🔼🔽

javaincrement and decrement
int num = 7;
num++;    // num = 8  (increment by 1)
num--;    // num = 7  (decrement by 1)

// These are shortcuts for:
num += 1;  // same as num++
num -= 1;  // same as num--

Works on char too! 'a'++ becomes 'b' because characters are internally numbers.

Section 10

Pre vs Post Increment — The Tricky Part 🎭

When ++ or -- is used as a standalone statement, both behave the same. The difference matters only when the result is assigned or used in an expression.

result = num++

Post-increment: first fetch the value, then increment.
result gets the old value.

vs

result = ++num

Pre-increment: first increment, then fetch the value.
result gets the new value.

javathe critical difference
int num = 7;

// POST-increment
int result = num++;
// result = 7 (fetched BEFORE increment)
// num = 8    (incremented AFTER)

// PRE-increment
num = 7;  // reset
int result = ++num;
// result = 8 (fetched AFTER increment)
// num = 8    (incremented FIRST)
Memory Aid
Post (num++) = "use it, then change it" — the old value is used in the expression.
Pre (++num) = "change it, then use it" — the new value is used in the expression.

When used alone (num++; on its own line), both do the same thing. The difference only shows up during assignment or as part of a larger expression.

= vs == — Don't Mix Them Up!

== is the comparison operator (checks if two values are equal).

Section 13

Short-Circuit Operators (&&, ||) ⚡

Java has single (&, |) and double (&&, ||) versions. The double versions are called short-circuit operators — they skip evaluating the second condition when the result is already determined.

&& Short-Circuit AND

  • If first condition is false → skips second
  • Why? Because false AND anything = false
  • Saves time — doesn't evaluate unnecessarily

|| Short-Circuit OR

  • If first condition is true → skips second
  • Why? Because true OR anything = true
  • Same optimization — takes the shortcut
Always Use Short-Circuit in Practice
From this point forward, always use && and || instead of & and |. They're faster and safer. The single versions evaluate both sides always, which wastes time and can cause errors if the second condition depends on the first being true.
Section 14

NOT Operator (!) 🔄

Reverses a boolean value. true becomes false, false becomes true.

javaNOT operator
boolean result = (5 > 8);   // false
System.out.println(!result);    // true (reversed!)
Section 15

Conditional Statements — if 🔀

The foundation of decision-making in programming. Your code's flow changes based on whether a condition is true or false.

▸ If Statement Flow
javaif statement
int x = 18;

if (x > 10) {
    System.out.println("Hello");
}
// Output: Hello (because 18 > 10 is true)
Curly Brackets Rule
If you have one statement inside if, curly brackets are optional. But if you have two or more statements, you must use curly brackets. Best practice: always use them to avoid bugs.
Java ≠ Python — No Indentation Dependency
Java doesn't care about indentation (unlike Python). Indentation is for humans reading the code. Java uses curly brackets { } to define blocks. But always indent properly — your future self will thank you.

Multiple Conditions with Logical Operators

javacombining conditions
int x = 18;
// x must be between 11 and 20 (inclusive)
if (x > 10 && x <= 20) {
    System.out.println("In range!");
}

Comments in Java

Use // for single-line comments. The compiler ignores everything after // on that line. Great for leaving notes in your code.

Section 16

if-else — Either This or That 🔀

javaif-else
int x = 5;
int y = 7;

if (x > y) {
    System.out.println(x);  // print bigger number
} else {
    System.out.println(y);  // Output: 7
}
Rules
if can exist alone. else cannot exist without an if. else has no condition — it catches everything that didn't match the if.
Section 17

if-else-if Ladder 🪜

When you need to check multiple conditions one after another. Classic example: finding the greatest of three numbers.

javagreatest of three numbers
int x = 8, y = 17, z = 9;

if (x >= y && x >= z) {
    System.out.println(x);
} else if (y >= z) {         // no need to check y >= x
    System.out.println(y);      // because if x was biggest,
} else {                        // we'd never reach here!
    System.out.println(z);
}
// Output: 17
Be an Efficient Programmer
In the else if block, we only check y >= z, not y >= x && y >= z. Why? Because if x were the greatest, the first if would have caught it. By the time we reach else if, x is already eliminated. Removing unnecessary checks saves time and resources.
Section 18

Ternary Operator (?:) — if-else in One Line ✨

When your if-else is just assigning a value based on a condition, you can write it in one line:

javaternary operator
int n = 4;

// Long way with if-else:
int result;
if (n % 2 == 0) {
    result = 10;  // even
} else {
    result = 20;  // odd
}

// Ternary — same logic, one line:
int result = (n % 2 == 0) ? 10 : 20;
//           condition    ? if-true : if-false
When to Use Ternary
Only for simple assignments based on a condition. If your if-else has multiple statements or complex logic, stick with regular if-else. Ternary is not a replacement — it's a shortcut for specific cases.
Section 19

Switch-Case Statement 🔀

When you're checking one variable against multiple exact values (not ranges), switch is cleaner and faster than a chain of if-else-if.

javaswitch-case — day of the week
int n = 3;

switch (n) {
    case 1: System.out.println("Monday");    break;
    case 2: System.out.println("Tuesday");   break;
    case 3: System.out.println("Wednesday"); break;
    case 4: System.out.println("Thursday");  break;
    case 5: System.out.println("Friday");    break;
    case 6: System.out.println("Saturday");  break;
    case 7: System.out.println("Sunday");    break;
    default: System.out.println("Invalid!");
}
// Output: Wednesday
Fall-Through Trap — Why break is Critical
Without break, once a case matches, Java executes all remaining cases below it — even ones that don't match! This is called fall-through. So if n = 2 and you forget break, you'd get Tuesday, Wednesday, Thursday, Friday, Saturday, Sunday, and Invalid all printed. Always add break after each case.
default — The Catch-All
default runs when none of the cases match. It's like the else of switch. No break needed for default since it's the last block.
Section 20

While Loop 🔁

Repeats a block of code while a condition is true. Checks condition before each iteration.

javawhile loop — print hi 4 times
int i = 1;             // 1. Initialize

while (i <= 4) {       // 2. Condition check
    System.out.println("hi " + i);
    i++;                 // 3. Increment
}
// Output: hi 1, hi 2, hi 3, hi 4
Infinite Loop Danger!
If you forget i++, the condition is always true and the loop runs forever — printing endlessly until your system runs out of memory. Always make sure the loop variable changes so the condition eventually becomes false.
Variable Scope
The variable i is declared outside the loop. So it's still accessible after the loop ends. After the loop, i will be 5 (the value that made the condition false). That's why printing i after the loop gives 5.

The + Operator for Concatenation

The + operator does double duty in Java: it adds numbers, but when one side is a String, it concatenates (joins) them. "hi " + 3 produces the string "hi 3".

Section 21

Do-While Loop 🔁✅

Same as while, but checks the condition after executing the block. Guarantees at least one execution even if the condition is false.

while

Check first, then execute.
Might execute zero times.

vs

do-while

Execute first, then check.
Always executes at least once.

javado-while — executes at least once
int i = 5;   // condition will be false immediately!

do {
    System.out.println("hi " + i);
    i++;
} while (i <= 4);   // ← semicolon required!
// Output: hi 5  (printed once even though 5 <= 4 is false!)
Don't Forget the Semicolon!
Unlike while, the do-while ends with while(condition); — note the semicolon after the closing parenthesis. This is easy to forget.
Section 22

For Loop — The Workhorse 🐴

The most-used loop. Combines initialization, condition, and increment into one compact line.

javafor loop anatomy
//      init;     condition;  increment
for (int i = 1;  i <= 4;     i++) {
    System.out.println("hi " + i);
}
// Output: hi 1, hi 2, hi 3, hi 4

Execution Order

  1. Init runs once at the very start (int i = 1)
  2. Condition is checked. If true → execute block. If false → exit loop.
  3. Block executes (your code inside { })
  4. Increment runs (i++)
  5. Go back to step 2. Repeat.

Starting from Zero — The Common Pattern

javazero-indexed loop
// Print 4 times, starting from 0
for (int i = 0; i < 4; i++) {
    System.out.println(i);  // 0, 1, 2, 3 (4 iterations)
}
// Note: i < 4 (not <=) when starting from 0!
Zero-Based Counting
Computers count from 0, not 1. When you start at 0 and want N iterations, use i < N (not i <= N). This pattern appears everywhere — arrays, strings, collections. Get used to it now.

Decrementing Loop

javacountdown
for (int i = 4; i >= 1; i--) {
    System.out.println("hi " + i);
}
// Output: hi 4, hi 3, hi 2, hi 1

Skipping Parts of for

Any part of the for loop can be empty — just keep the semicolons:

javainit moved outside
int i = 1;
for (; i <= 4; i++) {   // init skipped, just two semicolons
    System.out.println(i);
}
Section 23

Nested Loops 🔁🔁

A loop inside a loop. The inner loop completes all its iterations for each single iteration of the outer loop.

javanested for loop — 5-day work calendar
for (int i = 1; i <= 5; i++) {           // outer: days
    System.out.print("Day " + i + ": ");
    for (int j = 1; j <= 9; j++) {       // inner: hours
        System.out.print("\t" + (j+8) + "-" + (j+9));
    }
    System.out.println();   // new line after each day
}
The Clock Analogy
Think of days as the outer loop (Mon, Tue, Wed…) and hours as the inner loop (9, 10, 11…). Each day, the clock resets to 9 and counts through the hours. When the hours are done, the day increments and the clock resets again. That's exactly how nested loops work.
String + Number Concatenation Trap
When you write "text" + j + 8, Java concatenates left-to-right: it joins "text" with j first (making a string), then joins 8 — so j + 8 is never added as numbers! Fix: use parentheses to force arithmetic first: "text" + (j + 8).
Section 24

Which Loop to Use When? 🤔

🔢
for loop
You know the count (1 to 100, arrays, patterns)
📄
while loop
Unknown count — files, network, user input, databases
🔂
do-while
Must execute at least once — menus, retry prompts
Practical Reality
In real-world projects, for is used ~80% of the time. while handles file/database/network reads. do-while is rare — maybe a menu that shows at least once. All three can technically do the same thing, but choosing the right one makes your code's intent clearer to other developers.
Section 25

Debug Mode in VS Code 🐛

Debug mode lets you execute code one line at a time and watch variables change in real-time. It's the single most useful skill for understanding how loops and conditions actually work.

  1. Click on the line number in the gutter to set a breakpoint (red dot appears)
  2. Go to Run → Start Debugging (or press F5)
  3. Execution pauses at your breakpoint
  4. Use Step Over (F10) to execute one line and move to the next
  5. Use Step Into (F11) to dive inside a method call
  6. Watch the Variables panel on the left — see values change live!
When Confused by a Loop, Debug It!
If you're not sure what value i has at iteration 3, or why a condition evaluated to false — don't guess. Set a breakpoint, step through, and watch the variables. It's like slow-motion replay for your code.
